# `/skills` — installed agent-skills showcase

## Revision note

Originally designed as static-only content (a committed JSON file, no
backend). Revised: this content is now DB-backed, following the same
DB-is-source-of-truth pattern as `BlogPost`/`Project`/`NewsItem` — editable
via Django admin, with a committed markdown fallback snapshot regenerated by
`export_content` (same mechanism as blog posts). The "editing" story is:
open Django admin, edit the `description` textarea (markdown), save — the
next `export_content` run refreshes the committed fallback.

## Purpose

A dual-purpose page on wenxiao.link: CV-credible evidence of how the site's
owner extends and works with AI coding agents, and a genuinely browsable
showcase for any visitor. Lists everything installed in Claude Code on the
owner's machine — plugins, npx-installed skill packages, and self-authored
skills — grouped and filterable, with a handful of curated highlights.

## Scope

In scope: a new Django model + admin + API, a new frontend page + data
reader, a local scan script, and a management command that upserts scanned
data into the DB without clobbering hand edits.

Out of scope: Hasura, any in-app (non-admin) editing UI (no
`EditableItem`/`Reorderable` wiring — admin-only editing is enough, same
bar as `NewsItem`/`ExperienceItem` today), a per-skill detail page.

## Data model

### Backend: `content.AgentSkill` (Django model)

Mirrors `BlogPost`'s shape and editing story:

```python
class AgentSkill(models.Model):
    SOURCE_CHOICES = [
        ("plugin", "Plugin"),
        ("npx-package", "npx package"),
        ("self-authored", "Self-authored"),
        ("linked-project", "Linked project"),
    ]
    CATEGORY_CHOICES = [
        ("skill", "Skill"),
        ("command", "Command"),
        ("agent", "Agent"),
    ]
    slug = models.SlugField(max_length=220, unique=True)
    name = models.CharField(max_length=200)
    description = models.TextField(blank=True, default="")  # markdown; the thing you edit
    source = models.CharField(max_length=20, choices=SOURCE_CHOICES)
    origin = models.CharField(max_length=255, blank=True, default="")
    category = models.CharField(max_length=10, choices=CATEGORY_CHOICES)
    tags = models.JSONField(default=list)
    highlight_blurb = models.TextField(blank=True, default="")
    highlight_order = models.IntegerField(null=True, blank=True)
    published = models.BooleanField(default=True)
    order = models.IntegerField(default=0)
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
```

`slug` is derived from `origin`+`name` at creation (so same-named skills
from different origins don't collide) and is stable across re-syncs — it's
the upsert key.

Fields split into two groups by who owns them:
- **Detected** (`name`, `description`, `source`, `origin`, `category`) —
  refreshed every time the sync command runs, reflecting current machine
  state.
- **Curated** (`tags`, `highlight_blurb`, `highlight_order`, `published`,
  `order`) — set once via Django admin, never touched by the sync command
  after the row exists.

### API

`/api/content/agent-skills/` (list) and `/api/content/agent-skills/<id>/`
(detail), following the exact `ReadOnlyOrSuperUser` + `ListCreateAPIView`/
`RetrieveUpdateDestroyAPIView` pattern used by `ProjectListView`/
`ProjectDetailView`. Not `/api/content/skills/` — that path already serves
the unrelated career-`SkillGroup` model.

Public list returns `published=True` rows only (owner sees all via `?all=1`,
matching `BlogListView`).

### Fallback markdown

`export_content` (already runs daily + on content edits per
`backend/scripts/launchd/sync-content.sh`) gains a `content/agent-skills/
<slug>.md` dump — one file per published `AgentSkill`, same frontmatter+body
shape as `content/blog/<slug>.md`. `frontend/app/lib/content.ts` gains
`getAgentSkills()` mirroring `getBlogPosts()`: API first, file fallback
second.

## Local scan → DB sync

1. `frontend/scripts/export-agent-skills.mjs` (Node, already validated
   against this machine's real `~/.claude`/`~/.agents`) scans installed
   plugins and skills and writes a JSON array — no DB/HTTP calls, no
   merge logic (the Django side owns upsert/preservation).
2. `python manage.py sync_agent_skills --from-json <path>` (run via
   `docker compose exec platform ...`, matching how `sync_scholar` is run
   locally today) reads that JSON and upserts `AgentSkill` rows: creates
   new slugs with defaults, refreshes the *detected* fields on existing
   slugs, leaves *curated* fields untouched.
3. The owner reviews new/changed entries in Django admin, adds
   `tags`/`highlight_blurb`/`highlight_order` for standouts, unpublishes
   noise if any.

## Page

Unchanged from the original design: `frontend/app/skills/page.tsx` (server
component, reads via `getAgentSkills()`) → `SkillsClient.tsx` (client
component) rendering a single filterable/searchable catalog grouped by
`origin`, search over name/description/tags, chip filters for `source` and
`category`, curated (`highlight`) entries rendered inline with an accent
border and their `highlight_blurb` in place of `description`.

## Navigation

Added to `SiteHeader`'s nav link list alongside Home/Blog/Projects/
Publications, pointing at `/skills`.

## Testing

No frontend test framework exists in this repo (verify via `type-check`/
`lint`/manual browser check, matching every other frontend feature here).
Backend: no existing Django test suite pattern was found for `content`
either (matched by convention — this repo verifies content changes via
`docker compose` + manual `curl`/admin checks, not `pytest`). The sync
command's upsert-preserves-curation behavior is verified manually: run it
twice with an intervening hand-edit and confirm the edit survives.
